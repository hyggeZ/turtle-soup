# 性能基线（2026-11-16）

这份记录用于后续改动的同机对照。测试在 Windows amd64、Go 1.26.5、Intel Core Ultra 5 125H、本地 Docker `postgres:16-alpine` 上运行；PostgreSQL 端口为 5434。下列数字不是线上吞吐或容量承诺。

## 验收

设置 `TEST_DATABASE_URL=postgres://turtle:turtle_dev@127.0.0.1:5434/turtle?sslmode=disable` 后执行 `go test ./... -count=1`，全部通过。网页执行 `npm run build`，构建通过。桌面和 390×844 窄屏实际点验首页、社区、登录、建房、大厅、房间、后台及日志详情。

## 基准

| 场景 | 方法 | 原始耗时 | 中位数 | 分配 / 查询 |
| --- | --- | --- | --- | --- |
| 健康检查 | `go test ./cmd/server -run '^$' -bench '^BenchmarkHealth$' -benchmem -benchtime=1000x -count=5` | 43880、34328、30235、35836、31447 ns/op | 34328 ns/op | 2937–2981 B/op，26 allocs/op |
| 房间快照 | `go test ./internal/room -run '^$' -bench '^BenchmarkRoomSnapshot$' -benchmem -benchtime=100x -count=5` | 7619742、7527530、9762073、8908730、6609880 ns/op | 7619742 ns/op | 约 29745–30002 B/op，571 allocs/op，4 dbq/op |

房间快照使用同一个本地测试数据库。每轮有缓存、数据库后台任务和机器负载波动，因此后续对比应重复同一命令、关注分布和查询数，不把一次差异当作优化效果。

## 对局事件规模

执行 `SNAPSHOT_SCALE=1 go test ./internal/room -run '^TestSnapshotScale$' -count=1 -v`。每档测量 30 次；full 为完整快照，delta 为增量刷新。

| 事件数 | full 大小 | full P50 / P95 | delta 大小 | delta P50 / P95 | 查询数 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 102 | 22492 B | 10.24 / 12.15 ms | 914 B | 8.87 / 11.67 ms | 4 |
| 1002 | 218956 B | 38.09 / 46.36 ms | 914 B | 10.82 / 12.49 ms | 4 |
| 5002 | 1099807 B | 344.47 / 445.85 ms | 914 B | 8.58 / 10.02 ms | 4 |

5002 条时 full 的一份 `EXPLAIN ANALYZE` 结果中，执行时间 270.691 ms，其中 JIT 为 260.262 ms。这是后续可单独验证的优化线索；当前并未修改数据库配置或查询计划。

## 观测边界

- HTTP 健康检查基准不是端到端网络测量。
- 快照基准和规模测试使用本地 PostgreSQL，不能外推到云服务器。
- 日志、追踪和 UI 改动之后重新运行相同命令，并保留原始数据和回归结果。
