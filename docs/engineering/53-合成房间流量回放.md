# 第 370 条 合成房间流量回放

读压测分别测过题目列表和长局快照。加入房间回放后，还能用同一条固定轨迹验证读、写和重复提交在一局里的组合行为。[HTTP 读吞吐基准](31-真实HTTP吞吐基线.md)

每个合成房间按固定顺序发送六次 HTTP 请求。玩家先读快照，再提交提问。主持人从增量快照读到事件和待办。玩家用同一个操作 ID 重试，主持人对同一事件回复「是」，玩家从增量快照确认回复。测试使用前序响应返回的房间事件 ID 和游标，最后对照数据库中恰好两条事件和两个操作。不同房间独立，允许并行。

回放端只请求进程内测试服务器的回环地址，数据库也限定为回环地址上的专用 `turtle_e2e` 库。账号、Cookie、题目和操作均由夹具临时生成，无需输入历史日志。测量用于建立读写混合的可复现基线，生产请求路径沿用现有实现。

## 回放基线

在 Windows/amd64 上运行 Go 1.26.5，隔离 PostgreSQL 16.15 经 SSH 隧道连接。每批 16 局、96 次 HTTP，连接池上限 16。每轮先跑 1 路并发，再跑 4 路并发，各自另用新房间预热。三轮共 96 局、576 次正式请求，全部成功。另有 15 局预热通过。每局落库两条事件和两个操作，重试未产生额外记录，玩家快照没有汤底。测量期间连接池等待和取消数均为 0。

| 三轮中位数 | 1 路并发 | 4 路并发 |
| --- | ---: | ---: |
| 每批耗时 | 14.785 s | 4.526 s |
| 吞吐 | 6.49 请求/s | 21.21 请求/s |
| 全部请求 P95 | 356.00 ms | 453.31 ms |
| 读取 P95 | 301.40 ms | 333.61 ms |
| 首次写入 P95 | 438.43 ms | 483.94 ms |
| 重试 P95 | 353.65 ms | 174.07 ms |

两组跑相同的程序。4 路并发在这次环境中的吞吐约为 1 路的 3.27 倍，整体 P95 也约高 27%。每批只有 16 条重试，按最近秩取到的 P95 即该批最大值。绝对延迟受 SSH 隧道影响，可在同机同负载下继续用此程序做后续对照。

设置回环隔离库的 `TEST_DATABASE_URL`，再用下列命令单独运行。默认测试只编译此夹具，专用环境变量开启后才执行写负载。

```powershell
$env:ROOM_HTTP_REPLAY = '1'
go test -mod=readonly -v -count=1 -run '^TestRoomHTTPReplay$' ./cmd/server
```
