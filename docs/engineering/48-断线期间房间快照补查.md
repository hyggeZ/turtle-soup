# 第 334 条 断线期间房间快照补查

房间通过 WebSocket 接收更新提醒，实际内容仍由带身份和事件游标的 HTTP 快照提供。WebSocket 持续快速握手失败时，旧版每次失败都会重排 HTTP 补查。重连等待最多 30 秒，补查等待 30–60 秒。快照接口即使正常，也可能一直等不到请求。

只在已建立的 WebSocket 断开时切换到离线补查周期。后续握手失败只安排自己的重试。首次读取、每次快照读取完成和 WebSocket 成功恢复时，按各自状态安排下一次补查。离开房间时清理两种定时器。前端继续通过游标追赶遗漏事件，身份变化时丢弃旧视图并重读新身份可见的内容。

本项恢复了已有 HTTP 降级能力。持续断线时会产生原来被错误推迟的补查流量。每个客户端分散在 30–60 秒补查一次，并复用原有的单请求合并。WebSocket 重试频率沿用已验证的退避策略。[房间断线重连退避](11-断线重连退避.md)

## 前后对照

在同一台 Windows 测试机交替运行三对 Chromium。旧版固定在 `a497de6`，两侧使用各自的 Vue 生产构建和同一个回环故障夹具。浏览器真实发出 WebSocket 握手并收到 HTTP `503`，正常的 HTTP 快照返回测试房间并按游标提供一条新事件。固定抖动计算的随机值为 `0.5`，推进浏览器虚拟时钟 170 秒。两版每轮的结果均一致。

| 指标 | 旧版 | 新版 |
| --- | ---: | ---: |
| 首次读取之后的 HTTP 补查次数 | 0 | 3 |
| 首次补查用时 | 170 秒内未发生 | 45 秒 |
| WebSocket 握手次数，含首次 | 9 | 9 |
| 房间记录里渲染的新事件 | 0 | 1 |
| 离开房间再推进 120 秒后的额外快照或握手 | 0 | 0 |

新版在第 45、90、135 秒发起补查，事件游标从 `0` 推进到 `1`，后续读取保持 `1`。这是针对握手持续失败的功能回归和请求成本对照。计时使用浏览器虚拟时钟，实际网络延迟和并发承载量需单独测量。

本地 Vue 24 项测试、类型检查和生产构建通过。正常对局完整流程与握手故障各跑两轮，Chromium 合计 4/4 通过。在 `web` 执行 `npm run build` 后，可在 `e2e` 执行 `npm exec playwright test room-offline.spec.js` 独立复跑。常规浏览器验收自动覆盖这项用例。
