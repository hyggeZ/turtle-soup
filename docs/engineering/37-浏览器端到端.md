# 第 242 条 浏览器端到端回归

此前的 CI 分别运行 Go 集成测试和 Vue 测试。新增 Playwright 1.65.0 Chromium 作业，从浏览器依次操作 Vue 页面、Go 接口、PostgreSQL 和 WebSocket，验证这些组件连在一起时的行为。用例为房主、多人玩家、单人玩家和管理员分别建立会话。

| 步骤 | 浏览器验收 |
| --- | --- |
| 注册与登录 | 三个玩家账号都能注册、登录，网页各自维持会话 |
| 发布题目 | 作者发题成功，其他玩家能读汤面，页面和详情接口的响应都没有泄露该题汤底 |
| 多人共探 | 房主建房，玩家凭房间码加入，开局后能提问，主持收到实时更新 |
| 断线恢复 | 主持离开页面触发真实 WebSocket 断连。玩家看到对局暂停，主持返回后继续对局，旧提问只出现一次 |
| 单人 AI | 独立玩家开局和提问，Go 调用本地 Qwen 响应夹具，浏览器显示约定的「是」且不显示汤底 |
| 后台审核 | 普通账号被后台拒绝，管理员隐藏题目，随后玩家在页面和社区列表接口中都看不到该题 |

## 测试结果

本机 Windows 使用 Chromium 158 和隔离 PostgreSQL 16，连续三轮通过，用例分别耗时 18.3、12.5、12.1 秒。GitHub Ubuntu 24.04、PostgreSQL 16 上的同一用例通过，Playwright 总耗时 7.2 秒。以下是单个用例步骤的用时，和总耗时之间的差额包括启动浏览器和创建会话。

| 步骤 | Windows 三轮范围 | GitHub 单轮 |
| --- | ---: | ---: |
| 注册登录 | 2.5–7.8 s | 1.8 s |
| 发题和汤底隔离 | 690–810 ms | 455 ms |
| 建共探房并提问 | 3.8–4.8 s | 940 ms |
| 断线并恢复 | 1.1–1.2 s | 266 ms |
| 固定 AI 判定 | 912 ms–2.2 s | 295 ms |
| 后台权限与题目隐藏 | 1.6–1.7 s | 819 ms |

原有 Go 和 Vue 作业同时通过。同次 CI 中，Go 作业 57 秒、Vue 作业 20 秒，浏览器作业 92 秒，其中安装浏览器依赖 32 秒，构建并执行回归的步骤 15 秒。浏览器作业成为该次流水线的最长作业。新增时间发生在 CI，线上业务代码未变。 [通过记录](https://github.com/hyggeZ/turtle-soup/actions/runs/45096777776)

首次 GitHub 浏览器回归匹配到了两个含「发布题目」字样的首页按钮，改用精确的可访问名称后重新跑整条链路。该次执行成功上传约 10.24 MB 的追踪压缩包，确认按钮匹配失败时可以保留页面和操作记录。 [首次回归记录](https://github.com/hyggeZ/turtle-soup/actions/runs/45096452127)

本机又做了一次反向验证，在临时启动配置中将模拟 Qwen 的「是」换成「否」。前四步通过，第五步按预期失败，退出码为 1，生成约 20.91 MB 的 trace。页面快照能看到错误判定，确认测试能发现这一类浏览器与 API 集成回归。

## 运行方式

从仓库根目录安装网页依赖，再进入 `e2e` 安装和运行测试。`E2E_DATABASE_URL` 指向本机回环上的专用空库 `turtle_e2e`。启动器会初始化测试管理员并写入用例生成的账号、题目和对局，运行结束后可删除该临时数据库。

```powershell
Push-Location web
npm ci
Pop-Location
Push-Location e2e
npm ci
npx playwright install --only-shell chromium
$env:E2E_DATABASE_URL = 'postgres://测试用户:测试密码@127.0.0.1:15432/turtle_e2e?sslmode=disable'
npm test
Pop-Location
```

启动器将构建产物和服务日志写入临时目录，退出后回收进程和文件。CI 并行运行浏览器、Go 和 Vue 三个作业，失败时保存浏览器 trace 供定位。外部模型响应固定，模型真实准确率、延时和成本继续由独立的评测工具测量。
