# 第 457 条 大厅交互计时

已登录用户进入大厅时，公开房间和我的房间来自两个独立读取接口。原页面先等公开列表，再发起我的房间请求。现在同时发起两次读取，仍用原来的账号和加载版本检查决定是否应用结果。访客只请求公开列表。

浏览器对照分别记录两次请求的发起间隔、点击后列表就绪时间，以及 Chromium 能采到的 Event Timing。列表就绪包含异步接口等待，Event Timing 描述单次输入处理和呈现。两种计时分别报告。[W3C Event Timing](https://www.w3.org/TR/event-timing/)

同一台 Windows 机器、同一 Chromium Headless Shell 和两份真实 Vue 生产构建。旧版为 `ed613a8` 对应的前端产物，两个受控读取接口各等待 120 ms。每版登录和访客各跑三轮。登录时两请求都在首个响应前到达由 0/3 增至 3/3，访客两版都只发一个请求。候选 6/6 通过。

| 登录场景 | 旧版中位数 | 并行中位数 |
| --- | ---: | ---: |
| 两请求发起时间差 | 194.20 ms | 1.10 ms |
| 点击到公开列表出现在 DOM | 411.50 ms | 185.40 ms |
| 按交互 ID 汇总的 Event Timing | 72 ms | 88 ms |

在本次合成网络条件下，列表就绪的中位数下降 54.9%。单次交互的 Event Timing 样本量只有三条，候选未呈现更低的输入耗时。这组数据反映大厅特定交互，正式 INP 需用现场交互分布评估。Vue 24 项测试、类型检查和生产构建通过，入口增加 10 B。
