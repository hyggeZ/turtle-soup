# 评论正文的防剧透边界

## 问题与规则

旧实现按评论发布者填写的 `spoiler` 布尔值决定是否在 GET 列表里返回正文。真实 PostgreSQL 回归复现：把完整汤底写进 `spoiler=false` 评论后，正在这道题推理的玩家能直接从题目详情的评论列表读到汤底，且没有留下揭示记录。

评论正文现在一律按可能剧透处理。GET 列表保留作者、时间和剧透标记等元数据，正文始终为空；打开详情或翻页不会改变玩家资格。登录用户主动确认后，通过单条 POST 取得正文。该接口复用查看汤底的题目行锁和真人/单人 AI 活跃玩家检查：同题玩家收到 403；其他用户成功读取后在 `soup_reveals` 留下记录，不能再作为玩家进入这道题的其他对局。作者和已经接触汤底的旁观者也通过同一入口读取。服务端不依赖关键字或模型判断评论是否真的剧透。

前端默认折叠所有评论，每条单独确认；切换题目或账号时清除已展开的正文。成功的正文响应设置 `Cache-Control: private, no-store`。发布者原有的剧透标记只用于界面提醒，不决定权限。

## 验收与开销

- 旧实现上“未标记评论包含完整汤底”的真实 PostgreSQL 测试失败，列表 HTTP 200 含正文；修复后同一用例的列表正文为 **0**，匿名和真人等待中、进行中、暂停中的玩家均不能直接取得正文。
- 集成测试覆盖作者、已看底用户、离席旁观者、活跃单人 AI 玩家、错误评论/题目 ID，以及确认阅读后真人和 AI 同题入场资格。评论展开与建房、加入、AI 开局的并发用例重复 **10 次**通过；结果不能同时是“读到正文”和“取得玩家资格”。
- 本地真实 PostgreSQL 上 `go test ./... -count=1` 全部通过；`go test -race ./internal/forum -run 'TestUnmarkedCommentAccess|TestCommentAccessRacesWithPlayerEntry|TestSpoilerRequiresLeavingPlayerSeat' -count=1` 通过；`web` 的 `npm run build` 通过。
- 无数据库迁移或模型调用。评论列表仍是 **1 次查询**，不再读取或返回正文；相比旧版未标记评论，响应减少正文大小。首次查看每条评论增加一次主动 POST，沿用原剧透展开流程的评论读取与 `RevealAnswer` 事务（题目行锁、资格查询、幂等揭示记录）。没有稳定延迟对照，不能把响应变短推断为确定的提速。

账号之间无法互相证明是否已在别处看过汤底；本规则保证的是当前账号和服务端接口的资格一致性。主动确认评论会永久失去这道题的玩家资格，即使该条评论实际上没有剧透；这是在无法可靠自动识别任意文字剧透时选用的明确产品规则。
