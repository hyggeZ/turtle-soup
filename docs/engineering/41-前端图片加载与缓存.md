# 前端图片加载与缓存

首页、房间和详情页的大图原来直接使用 PNG。按钮图片通过 `public/assets` 发布，地址随版本保持固定。窄屏题目详情会隐藏证物插画，普通 `<img>` 仍会提前发起下载。

- 三张大图转换为 WebP Q89，使用 Pillow 12 和 libwebp 1.6，保留原尺寸、构图与逐像素透明度。深色底图与按钮仍沿用现有画面和布局。
- 图片由 Vite 从 `src/assets` 打包，构建输出使用内容哈希。入口、房间或详情按各自模板引用图片。非关键装饰图使用原生懒加载、异步解码与尺寸属性。 [Vite 静态资源处理](https://v6.vite.dev/guide/assets.html) · [MDN 延迟加载](https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/Lazy_loading)
- Nginx 为内容哈希资源返回 `public, max-age=31536000, immutable`。HTML 使用 `no-cache` 重新验证入口。缺失的资源直接返回 404，路径不会落到 SPA 的 HTML。 [Nginx 响应头](https://nginx.org/en/docs/http/ngx_http_headers_module.html#add_header) · [RFC 8246](https://www.rfc-editor.org/rfc/rfc8246)

## 图片体积

| 图片 | 原 PNG | WebP Q89 | 减少 |
| --- | ---: | ---: | ---: |
| 首页背景（1,672 × 941） | 2,321,370 B | 250,808 B | 89.2% |
| 房间背景（1,672 × 941） | 1,734,799 B | 96,976 B | 94.4% |
| 证物图（1,536 × 1,024） | 2,776,447 B | 423,022 B | 84.8% |
| **合计** | **6,832,616 B** | **770,806 B** | **88.7%** |

对照 Q86、Q89、Q92 后采用 Q89。三张图的 PSNR 分别为 36.27、41.86、35.27 dB，证物图在页面使用的深色背景上合成后比较。三张图片的 Alpha 通道完全一致。

## Chromium 实测

基线为 `99da186` 的独立生产构建。Chromium 158 使用桌面 1,440 × 900 和手机 390 × 844 视口，下行 8 Mbps、上行 3 Mbps、额外延迟 45 ms。每个视口交替运行 5 对首页样本和 3 对详情样本。冷访使用新浏览器上下文。图片传输量使用 Resource Timing，包含响应头。

| 指标 | 桌面基线 / 优化后 | 手机基线 / 优化后 |
| --- | ---: | ---: |
| 首页冷访图片请求数 | 7 / 7 | 7 / 7 |
| 首页冷访图片传输 | 2,915,602 / 845,040 B | 2,915,602 / 845,040 B |
| 首页冷访 LCP 中位数 | 1,660 / 1,472 ms | 1,332 / 1,296 ms |
| 首页背景下载完成中位数 | 3,746 / 1,483 ms | 3,630 / 1,474 ms |
| 详情证物图传输 | 2,776,747 / 423,322 B | 2,776,747 / 0 B |

首页冷访的图片传输下降 71.0%。浏览器测到的 LCP 元素是票券，手机 LCP 的样本差值小于两组波动。首页背景的下载用时单独记录。详情证物图桌面仍在首屏，点击详情到图下载完成的中位数从 3,032 降至 615 ms。手机详情滚动前后均未请求原本隐藏的证物图。

在相同的本地 3,600 秒缓存条件下，两版首页重复访问的网络图片请求和传输均为零。首页和后台各用两种视口冷访，首页仅加载自身图片，后台只请求房间底图。房间、单人和详情在三个屏幕宽度下的 9 组插画尺寸及裁切对照通过。Vue 24 项测试、类型检查、生产构建和完整 Chromium 游戏流程均通过。

## 缓存验收

使用临时回环 Nginx 1.24.0，配置语法及 8 项实际 HTTP 检查通过。带哈希的 WebP 和 CSS 均返回长期缓存头。无哈希文件正常响应；有哈希和无哈希的缺失图片均返回 404。`/`、`/admin`、`/index.html` 都返回 `no-cache`。
