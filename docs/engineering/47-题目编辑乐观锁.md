# 第 329 条 题目编辑乐观锁

作者打开编辑页时读取题目版本，保存时提交读取到的版本。PostgreSQL 迁移为现存题目初始化版本 `1`。服务端在已有题目行锁中核对作者、审核状态和保存版本，成功保存后版本加一。作者详情含汤底和编辑版本，因此声明 `private, no-store`。进行中对局继续限制编辑，公开详情沿用原先的可见字段。

| 请求 | 响应 |
| --- | --- |
| 作者保存从当前版本读取的内容 | `200`，保存内容并返回新版本 |
| 另一个编辑页先保存 | `409`，错误码 `SOUP_VERSION_CONFLICT`，继续保留浏览器草稿 |
| 旧编辑器未提交版本 | `428`，提示保留草稿后重新打开编辑页 |
| 版本格式无效 | `400`，按请求错误处理 |

冲突时可以打开只读的最新版本和草稿对照。用户明确确认替换后，页面才把最新内容装入表单。再次保存由用户发起。仲裁发生在数据库事务内，两个页面同时提交同一个版本时只有第一份成功保存的修改能写入。 [HTTP 428](https://www.rfc-editor.org/rfc/rfc6585.html#section-3) · [HTTP 409](https://www.rfc-editor.org/rfc/rfc9110.html#name-409-conflict)

## 验收

- 隔离 PostgreSQL 连续 3 轮验证 8 和 16 个编辑请求同时提交同一版本，每批均只有一个保存成功。重读版本后可以提交新修改。覆盖旧数据库迁移、非作者与匿名详情、缺失或非法版本、题目审核和活跃对局限制。
- Chromium 的完整流程连续通过 2 轮，覆盖双标签页冲突、预览与取消，另在 320 px 视口验证预览请求失败时保留草稿，以及确认替换后由用户再次保存。Vue 24 项测试、类型检查和生产构建通过。
- 单个正常编辑仍只需一次读取和一次保存。冲突预览由用户触发，额外读取一次；确认替换仅改变页面状态。构建产物原始 JavaScript 增加 2,377 B，CSS 增加 525 B。

## 同版本并发写入对照

在同一台 Windows 测试机用 Gin 处理 HTTP 请求，数据库为隔离 PostgreSQL 16，经 SSH 隧道连接。旧版固定在 `345c03f`，两端发送相同的版本字段和长度相当的草稿。每批先用另一道题预热，再向同一道题并发提交 16 份草稿。旧版和新版交替执行 3 对。SQL 统计包括论坛事务的开始和提交或回滚，认证连接池单独统计。

| 指标 | 旧版 | 新版 |
| --- | ---: | ---: |
| 每批成功响应 | 16 | 1 |
| 每批版本冲突 | 0 | 15 |
| 每批被后续保存覆盖的成功编辑 | 15 | 0 |
| 每批论坛 SQL 次数 | 96 | 51 |
| 16 请求批次总耗时中位数 | 2,030.16 ms | 591.40 ms |

成功保存仍需 6 次论坛 SQL，过期版本只需 3 次。新批次提前拒绝 15 次过期写入，所以上表衡量同版本竞争时的响应和写入成本。测试使用远端数据库隧道，时间受网络往返影响，只能与本次同条件对照比较。

设置 `SOUP_EDIT_PERF=1` 和隔离库的 `TEST_DATABASE_URL` 后，可单独执行 `go test -v ./internal/forum -run '^TestSoupEditVersionPerformance$'`。旧版复测需要复制两个测量与回归测试文件到旧版工作区，并只运行测量用例。
