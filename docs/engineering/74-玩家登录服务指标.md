# 第 739 条 玩家登录服务指标

现有指标汇总所有 HTTP 状态，并分别统计入房和 AI 判定。新增 `operation="login"`，只记录玩家登录路由，按成功、业务拒绝、服务错误分类，并记录相同请求耗时。密码错误和限流归入拒绝，便于独立观察。指标不包含用户名、请求参数、Cookie 或客户端地址。已有回环 Prometheus 监听可以直接抓取。

在合成请求中，玩家登录返回 200、401、429、503 各一次，后台登录另返回 200 一次。旧版没有独立登录序列，新版三个计数分别为成功 1、拒绝 2、服务错误 1。后台登录未计入。Go 遥测和服务入口回归通过。

例行观察可用 `ok / (ok + error)` 表示排除业务拒绝的登录服务成功比例，拒绝次数单列。窗口内没有有效分母时没有可解释的成功率。以下查询用于已有 Prometheus，当前未据此设生产指标目标。

```promql
sum(increase(turtle_operation_duration_seconds_count{operation="login",outcome="ok"}[5m]))
/
sum(increase(turtle_operation_duration_seconds_count{operation="login",outcome=~"ok|error"}[5m]))

histogram_quantile(0.95, sum by (le) (rate(turtle_operation_duration_seconds_bucket{operation="login",outcome="ok"}[5m])))
```

同一台 Windows 机器用旧、新二进制交替跑五轮，每项 300 ms、单 CPU。结果为中位数，计时范围是进程内的观察函数。

| 路由 | 原版 | 候选 |
| --- | ---: | ---: |
| 登录 | 14.85 ns/op | 41.17 ns/op |
| 入房 | 39.95 ns/op | 38.07 ns/op |
| 公开题目读取 | 13.75 ns/op | 14.34 ns/op |

三条路径两版均为零分配。新增登录统计多用约 26 ns，来自直方图计数。入房和公开读取的两版范围均重叠。报告没有把微基准变化换算成登录端到端延迟。
