# 第 100 条 Agent 验证集和质量对照

原 `ai-eval` 的 `-limit` 只改变送给模型的样例数量。少量冒烟与全量报告会记录同一个 `evalSetHash`，下游只核对这个字段时容易把两份结果当成同范围。新的 `scope` 记录题集、实际样例数、是否全量以及实际入选样例的内容指纹。顺序、输入、历史或人工标签变化都会生成新指纹。原开发集与 `evalSetHash` 保留，旧报告可继续查看。

- `dev` 是默认开发集，保留原有 144 条。`holdout` 是独立验证集，新增 4 个原创故事、24 条样例，6 类人工标签各 4 条，其中两条包含 14 轮历史。验证集用于独立复核，报告仍只输出样例 ID 和判定等统计字段。
- `compare` 从两份本地报告重新核对逐例结果。双方须来自当前同一全量题集，样例 ID、顺序、类型和人工标签均一致。范围字段缺失的历史报告需要按新工具重跑才能参加比较。
- 对照时检查候选的调用失败、错误通关是否增加，正确还原命中、总命中是否下降。问答、正确还原、非正确还原都须有有效结果。对照可以跨模型及提示词版本。Token 和延迟随结果输出，供人工评估取舍。

```powershell
go run ./cmd/ai-eval -suite holdout -out baseline.json
go run ./cmd/ai-eval -suite holdout -out candidate.json
go run ./cmd/ai-eval compare baseline.json candidate.json
```

首次命令应在基线版本或配置下运行，第二次切换待评估版本或配置。对照命令仅需要两份报告。质量回归时它会输出原因并返回非零退出码。

## 离线回归和性能

固定答案回放覆盖 24 条验证样例。对照用例覆盖全量匹配、抽样、旧报告、缺失结果、ID 变化、超时、错误通关、漏判、无有效还原。开发集的 1、2、144 条产生三个不同的范围指纹。相同选取重复运行时指纹可复现。

固定已加载的题集，单线程运行 7 轮，每轮 300 ms，比较原始开发集指纹与新增范围指纹后的开销。

| 实际运行的样例数 | 中位耗时（µs/次） | 分配字节（B/次） | 分配次数 |
| ---: | ---: | ---: | ---: |
| 1 | 17.472 → 18.730 | 160 → 632 | 3 → 8 |
| 2 | 18.473 → 20.744 | 160 → 952 | 3 → 8 |
| 144 | 18.914 → 169.113 | 160 → 65,854 | 3 → 8 |

全量报告新增约 0.15 ms 和 64 KiB 分配，主要用于把样例序列化后计算指纹。该代码随评测命令执行一次，游戏请求路径没有接入这项计算。

## 百炼验证集基线

在 `mine` 用已有配置单独运行评测进程。`qwen-plus`、提示词 `v2`，完整验证集指纹 `3379c61de4d326391adfde8a64c6d659e421a8a18cad2f1fa6b9d6fe006bf975`。

| 指标 | 实测 |
| --- | ---: |
| 总命中 | 23 / 24（95.83%） |
| 调用失败 | 0 / 24 |
| 错误通关 | 0 / 8 |
| 正确还原召回率、精确率 | 4 / 4、4 / 4 |
| 模型调用 P50、P95 | 411.49 ms、811.58 ms |
| 输入、输出 Token | 8,467、124 |

唯一错判是 `holdout_clock_question_yes`，人工标注为「是」，模型返回「无关」。这道题的代号出现在 14 轮历史的前两轮，当前模型调用只取最近 12 轮，实际没有向模型传入代号含义。它可以作为后续验证长历史处理方式的固定用例。上述数字来自 4 个故事的一轮调用，模型版本对比使用同一验证集另行测量。
