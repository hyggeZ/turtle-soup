# 第 245 条 房间快照接口契约

房间页面会在进入房间、翻阅历史、接收 WebSocket 更新和处理主持待办时读取 `GET /api/rooms/{id}`。接口与页面之间此前各自维护测试样例。这次将当前使用的请求参数和关键响应字段固化到一份版本化 JSON，供 Go 接口测试和 Vue 测试共同读取。

| 场景 | 契约 |
| --- | --- |
| 首页和旧历史页 | `history=2` 返回 `historyBefore`，`0` 表示没有更早的页 |
| 增量追赶 | `after` 与 `hasMoreNew` 跟踪原始事件，即使过滤权限后看不到本页内容，游标也要继续推进 |
| 主持待办 | `tasks=1` 读取待办，`tasksAfter` 与事件游标各自分页 |
| 汤底与权限 | 主持在夹具场景下能读到汤底，玩家收到空字符串。未登录请求返回 401，未加入房间的已登录用户返回 404 |
| 无效输入 | 同时传 `before` 和 `after` 返回 400 和约定的错误体 |
| 旧版请求 | 单独传 `after` 保持现有响应格式 |

Go 在一次性 PostgreSQL schema 中构造房间和事件，通过实际路由检查 HTTP 状态和 JSON。Vue 使用同一批样例验证现有路径生成和游标判断逻辑。WebSocket 继续发送现有的 `changed` 通知，客户端收到通知后读取快照，由既有 WebSocket 集成测试覆盖。

## 独立回归与开销

- Go 在隔离 PostgreSQL 16 上重复 5 轮，真实 HTTP 样例 45/45 通过。每轮 9 个用例，含建表和造数的耗时中位为 3.77 秒，范围为 3.39–4.12 秒。
- Go 用四种合成错误验证断言的区分能力。省略 `hasMoreNew: false`、返回 `events: null`、省略 `historyBefore: 0`、待办游标停在原位。每种重复 5 次，共 20/20 次拒绝。
- Vue 共 24 项测试通过，原有 14 项，新增 9 个共享场景和 1 个契约版本检查。临时在内存中分别改动两个分页游标和空增量游标，删除待办字段，改名 401 的错误字段。5 种改动均使对应前端测试失败。这组实验针对共享样例的消费逻辑，Go 单独核对实际响应。
- Windows Node 22.14.0 暖机后交替运行 9 组前端测试。耗时中位从 243.0 ms 增至 278.1 ms，配对差值的中位数为 35.1 ms。网页构建通过，前后 JS 和 CSS 的 SHA-256 完全一致，分别为 205,048 字节和 93,213 字节。
