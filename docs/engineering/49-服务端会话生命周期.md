# 第 335 条 服务端会话生命周期

浏览器保存 HTTP Cookie，PostgreSQL 保存会话令牌哈希、所属账号和到期时间。登录创建会话，退出删除当前设备的会话。后台修改密码后，会话删除与密码更新由同一笔事务完成。HTTP 和 WebSocket 心跳读取同一个会话来源。[WebSocket 会话撤销](04-WebSocket会话撤销.md) · [后台操作审计](44-后台操作审计.md)

本条保留现有会话实现，为隔离 PostgreSQL 补充三条独立 HTTP 回归。用真实登录取得 Cookie，再经过 Gin 路由检查响应。过期测试只修改该条测试会话的数据库到期时间，因此可以确定地验证过期行为。

| 场景 | 验收行为 |
| --- | --- |
| 会话过期 | 仍持有原 Cookie 的请求返回 `401` |
| 主动退出 | 返回 `204` 并清除 Cookie。重放旧 Cookie 返回 `401`，同账号另一设备仍可访问 |
| 后台改密码 | 两台设备持有的旧 Cookie 立即返回 `401`。旧密码无法登录，新密码可以登录，管理员的独立会话仍有效 |

独立覆盖从 0 条增至 3 条，隔离 PostgreSQL 16 连续三轮共 9/9 通过。单轮用时 6.98、6.94、6.92 秒，包含建立临时 schema、执行迁移、bcrypt 和 HTTP 路由测试。生产路径的 SQL、会话期限与 Cookie 设置均沿用原代码，以上数字是回归成本。

设置隔离库的 `TEST_DATABASE_URL` 后，可运行 `go test ./internal/admin -run '^TestSessionLifecycleWithPostgres$' -count=3 -v` 复验。常规 Go 集成测试也会执行这三条用例。
