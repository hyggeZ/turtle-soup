# 第 039 条 AI 判定并发隔离实验

现有单人模式限制同一局的并发判定，也限制账户和全站的每日调用量。不同账号和对局仍能同时请求模型。第 039 条讨论用固定工作并发隔离慢模型。候选实现用 Go 有界通道控制名额，每个进程最多处理 8 个判定，满载的新请求返回 429。已提交结果的重放和主动揭底继续走原有操作检查，拒绝发生在扣减模型额度之前。

## 对照实验

使用 `0ce6e7d` Go 源码和同一份目标代码的候选版，在同一台 Linux 服务器、独立 PostgreSQL 16 测试库交替执行 3 轮。应用连接池最多 8 个连接，各轮有 1000 道合成题，并同时发出 24 个不同账号与对局的判定。假模型固定等待 350 ms，无百炼请求。另用同一个真实 Gin HTTP 测试服务每 20 ms 发 1 次匿名题目列表请求，共 60 次。验证列表状态和正文一致，成功判定与实际模型调用、数据库额度一致，结束后没有残留租约。

| 指标 | 现有版 | 限并发候选 |
| --- | ---: | ---: |
| 模型并发峰值 | 24 | 8 |
| AI 每轮响应 | 24 个 200 | 8 个 200，16 个 429 |
| AI 每轮扣减调用额度 | 24 | 8 |
| 成功 AI 请求 P95，三轮中位数 | 396.099 ms | 380.285 ms |
| 混合负载下列表 P95，三轮中位数 | 2.492 ms | 2.028 ms |
| 混合负载开始后的前 400 ms 内列表 P95，三轮中位数 | 3.855 ms | 3.829 ms |
| 混合批次 pgx 连接获取总时间，三轮中位数 | 539.742 ms | 232.878 ms |
| 混合批次 pgx 连接获取次数 | 180 | 132 |

每轮 60 次普通请求均成功，普通列表 P95 的三轮逐次值为 1.958、2.492、2.619 ms，候选为 2.028、2.669、1.770 ms。各轮结果交叠，短时突发区间的中位 P95 基本相同。候选的连接获取总耗时下降 56.9%，同时有三分之二的 AI 请求走了提前拒绝。成功请求统计排除了 429，不能据此把拒绝算成 AI 提速。

## 决定

本轮撤回候选。限制峰值确实有效，代价是 24 个能全部完成的判定里 16 个被立即拒绝。现有数据没有证明普通接口明显受益，也没有证明线上已达到模型并发上限。若以后出现可重复的模型限流或持续连接池等待，再比较短时排队和直接拒绝，并记录已完成请求比例、排队耗时和上游错误率。

两份实验源码、`TestWorkerLoadWithPostgres` 和逐轮原始结果保存在本地 `.local/baseline-20261118/worker/`。
