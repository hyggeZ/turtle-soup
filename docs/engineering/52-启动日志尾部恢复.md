# 第 366 条 启动日志尾部恢复

Go 服务在对外监听前恢复后台的近期请求。旧版按写入顺序扫描两代 JSONL，最多扫描 20 MiB，解析所有可读记录后保留最后 300 条。正常运行时，后台继续使用这 300 条请求做近期统计和链路查询。

启动时先从当前文件尾部向前按块读取。找满 300 条有效记录就停止，当前文件不足时再读上一代，最后恢复为原追加顺序。每块 64 KiB，跨块行最多暂存 1 MiB 的行数据。坏行、超长行和缺少 Trace ID 的记录跳过，后面的合法记录仍可恢复。

当前文件缺少末尾换行时，启动补一个行分隔符。完整旧行可以保留，半写的旧行依然会被跳过，随后写入的新记录从独立一行开始。上一代文件只读。日志仍使用原有 JSONL 格式与两代轮转。

## 日志恢复开销

旧版固定为 `1c5585b`，两侧使用同一个 `NewStore` 基准和完全一致的合成日志。Windows/amd64 上交替跑六对，每组十次，报告各轮 P50 和 Go 分配量的中位数。文件先生成并预读，系统页缓存保留。

| 负载 | 指标 | 全量扫描 | 尾部恢复 |
| --- | --- | ---: | ---: |
| 65,416 B，104 条 | 恢复 P50 | 1.795 ms | 1.627 ms |
| 小日志 | 分配量 | 235,505 B/op | 235,975 B/op |
| 20,970,860 B，33,340 条 | 恢复 P50 | 341.050 ms | 3.891 ms |
| 接近轮转上限 | 分配量 | 49,468,718 B/op | 472,612 B/op |
| 接近轮转上限 | 分配次数 | 767,008 allocs/op | 6,918 allocs/op |

小文件两组耗时范围重叠。大文件的两版均恢复同一组最近 300 条记录，恢复耗时下降约 98.9%。当前文件有足够记录，候选只需读文件末尾的三个 64 KiB 块。196,608 B 是按合成数据和读取块计算的逻辑字节数，实际磁盘吞吐未测。

```powershell
go test -mod=readonly -run '^$' -bench '^BenchmarkRestore' -benchmem -benchtime=10x -cpu=2 ./internal/telemetry
```

## 整体启动对照

从同一 `1c5585b` 构建真实 `cmd/server`，候选只替换本次日志恢复实现。两端使用同一隔离 PostgreSQL 16、同一回环端口和内容相同的两代合成日志。每代约 9.8 MiB、22,535 条。两版各预热一次，交替启动七对，从启动新进程计时到 `/health` 首次返回成功，每轮完成后关闭进程。

| 指标 | 全量扫描 | 尾部恢复 |
| --- | ---: | ---: |
| 到首次 `/health` 成功的中位数 | 1,011.143 ms | 685.391 ms |
| 七轮范围 | 924.855–1,283.500 ms | 611.094–893.188 ms |

七对均有下降，中位数下降 32.2%。这个耗时包含启动连接、迁移检查、房间恢复与健康探测。系统文件缓存保留，数据库经 SSH 隧道连接，数据适用于本次固定日志负载和测试环境。

## 恢复回归

专项用例覆盖旧格式和 CRLF、跨块长行、没有末尾换行的完整记录、半写末行、超长坏行、仅上一代、双代合并与 300 条上限。使用真实 Gin 中间件在重启后写一条记录，再次重启验证旧合法记录和新记录均可见。

原版实测在完整尾行和半写尾行这两种情况下都会丢失重启后的第一条新记录，遇到超长坏行还会遗漏其后的可读记录。这三个专项场景由 0/3 通过增至 3/3。候选全部 12 项专项用例通过，竞态检测重复五轮通过。
