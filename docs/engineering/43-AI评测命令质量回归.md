# 第 281 条 AI 评测命令质量回归

CI 编译 `ai-eval`，再通过真实命令行执行 `-suite holdout -out` 和 `compare`。测试沿用现有 24 条独立验证集，将模型 URL 指向本机回环上的固定 Qwen 响应。每次生成报告都会核对题集指纹、提示词版本、模拟模型版本和用量。对照阶段只读取已经写好的报告。

| 场景 | 预期 |
| --- | --- |
| 等价候选 | 24 项命中，命令退出码为 0，JSON 中 `passed` 为 `true` |
| 一条问答的模型调用失败 | `compare` 退出码为 1，指出调用失败数增加 |
| 一条错误还原被判正确 | `compare` 退出码为 1，指出错误通关数增加 |
| 一条正确还原被判不完整 | `compare` 退出码为 1，指出正确还原命中减少 |

这条回归覆盖 CLI 参数、HTTP 调用、报告落盘、报告兼容检查、质量判定与进程退出码。样例和响应均为测试夹具，本地调用次数可以逐笔核对。

单轮实际生成 5 份完整报告，发出 120 次回环 HTTP 调用。四次比较中，等价候选通过，三种退化全部拦截，比较阶段新增模型请求为零。测试还核对了逐例标签，以及报告不会写入测试密钥和汤底。

## 验收开销

Windows Go 1.26.5，编译后的同一测试二进制预热后交替执行 7 组。基线启用现有 holdout 评测和报告对照，候选再加 CLI 进程回归。两组均使用回环模拟服务，计时包括测试进程启动和报告读写。

| 测试范围 | 耗时中位数 | 七轮范围 |
| --- | ---: | ---: |
| 现有用例 | 212.13 ms | 190.11–257.58 ms |
| 加入实际 CLI 质量门槛 | 740.92 ms | 622.16–807.94 ms |

两组中位数相差 528.79 ms。七组运行均通过，开销属于新增回归。

## 独立执行

```powershell
New-Item -ItemType Directory -Force .local | Out-Null
$env:AI_EVAL_BINARY = Join-Path (Get-Location) '.local/ai-eval.exe'
go build -mod=readonly -o $env:AI_EVAL_BINARY ./cmd/ai-eval
go test -mod=readonly -count=1 -v ./cmd/ai-eval -run '^TestAIEvalCLIQualityGate$'
```
