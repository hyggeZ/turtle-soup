# 房间快照的权限一致性

## 问题与修复

快照原来先查询当前用户的房间身份，再分别查询成员与事件。PostgreSQL 默认的 `READ COMMITTED` 会让每条语句看到不同的提交时点。主持交接时，旧主持的在途请求可能保留 `role=host`，却读到交接后玩家提交的私有还原。

新增确定性并发测试：在旧主持读完身份后暂停请求，依次批准新主持、开局、由玩家提交私有还原，再放行旧请求。修复前 HTTP 200 同时含旧 `myRole=host`、新成员身份和私有正文；修复后旧请求只能看到交接前的事件，新的旧主持请求会按旁观者权限过滤，新主持仍可查看还原。

快照现在用同一个 `REPEATABLE READ READ ONLY` 事务读取身份、成员和事件。竞答回合已过期时，先结束只读事务，由原有写事务推进回合，再开一个新的只读事务读取；一次请求最多尝试推进一次。事务提交后才发送 JSON。该方案不阻塞主持交接，也不把汤底权限交给前端判断。

## 验收

- 新并发测试在旧实现上稳定失败，修复后通过。
- 并发测试和竞答到期测试各重复 3 次通过。
- 本地 PostgreSQL 上 `go test ./... -count=1` 全部通过。
- `go test -race ./internal/room -run 'TestOldHostSnapshotDoesNotSeeNewPrivateRestore|TestCompetitiveTurnAdvanceAndRestore' -count=1` 通过。

## 性能对照

同机 Windows amd64、Go 1.26.5、Intel Core Ultra 5 125H、Docker PostgreSQL 16。每版固定 100 次房间快照，共 5 轮；长局每档测量 30 次。原始结果如下。

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 10 事件快照的 5 轮耗时，ms/op | 13.11、6.82、28.70、9.17、5.91 | 11.68、10.13、8.82、5.37、6.99 |
| 10 事件快照中位数 | 9.17 ms | 8.82 ms |
| 数据库操作 / 快照 | 4 | 6 |
| 分配 / 快照 | 571 | 576 |
| 5002 事件完整快照 P50 / P95 | 217.57 / 325.93 ms | 215.20 / 409.68 ms |
| 5002 事件增量快照 P50 / P95 | 6.53 / 20.72 ms | 7.14 / 11.43 ms |

延迟离散很大，单轮 P95 变化不能归因于这次修复，也不能据此声称提速。可稳定解释的成本是事务 BEGIN/COMMIT 让每次数据库操作从 4 增至 6、分配增加 5 次。权限泄漏已被确定性测试消除，因此保留修复。长局完整快照仍需进一步优化；下一项可验证回答事件 `parent_id` 索引，但必须单独测量。
