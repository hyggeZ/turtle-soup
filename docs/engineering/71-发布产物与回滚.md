# 第 672 条 发布产物与回滚

原发布脚本可以用相同版本号改写活动目录，回滚仍会指向该目录。现在由服务器的发布目录提供互斥锁，重复版本号直接拒绝。每次使用新的网页解包目录，在同一文件系统内暂存二进制和网页。准备完毕后原子移动到正式目录，再切换当前版本链接。

切换后的探活最多运行 20 轮，单个 HTTP 探测最多 3 秒。探活失败或脚本收到可捕获的中断信号，脚本恢复上一个版本链接并尝试重启。如果首次发布失败，则撤销这次创建的链接并停止服务。已准备的失败版本仍可供检查，后续发布使用新版本号。

| 隔离对照 | 原脚本 | 新脚本 |
| --- | --- | --- |
| 重发当前版本号 | 当前二进制 SHA-256 前缀由 `168ca3a0` 变为 `fce48ce9` | 拒绝，原哈希保留 |
| 网页解包目录已有旧文件 | 旧文件进入新发布 | 旧文件未进入新发布 |
| 已有版本时连续 20 次探活失败 | 切回旧链接，旧文件可能已经被重发覆盖 | 切回已验证版本，产物哈希一致 |
| 首次发布探活失败 | 当前链接指向自身 | 撤销当前链接并停止服务 |
| 复制中断、并发发布、切换后 TERM、旧版重启失败 | 本次基线只采集上四种 | 未留下半成品、抢占被拒绝、中断回退、重启失败明确提示 |

WSL 隔离夹具使用真实 Linux 文件移动、链接与 `flock`，并模拟 systemd、HTTP 和数据库。旧脚本记录 4 个场景，约 0.895 秒。新脚本 8/8 通过，约 1.435 秒。两次执行覆盖范围不同，耗时只反映夹具规模。验证未覆盖服务器断电、进程强杀或生产重启时间。

本地原始夹具保存在 `.local/release-672-fixture.sh`，可在具备 GNU Bash、coreutils 和 `flock` 的本地 WSL 环境复跑。基线源码提交为 `92a2880`，使用同一夹具的 `baseline` 参数。
