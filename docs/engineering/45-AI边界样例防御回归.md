# 第 304 条 AI 边界样例防御回归

`ai-eval` 增加 `-suite boundary`，从既有开发集单独取出四个故事、36 条样例。开发集和独立验证集的内容、顺序与指纹通过对照校验。边界报告按故事列出标签命中、未获得有效判定、无效输出、应通关却漏判和不应通关却误判的条数。

- 生成报告沿用原题集校验和脱敏字段。`compare` 要求完整的同一题集，复核样例及故事分组指纹。
- 边界对照从逐例结果重算分组。一组增加的错误通关或漏判会报告组名，另一组改善时仍能定位这项退化。
- 真实命令行回归使用本机回环的固定模型响应。正例核对四个故事的指标。负例分别模拟一条误通关和一条无效响应，检查输出报告和真实比较退出码。四组统计来自已有游戏样例和本地替身。

## 回归结果

| 场景 | 标签命中 | 错误通关 | 正确还原漏判 | 无效输出 | 对照退出码 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 等价候选 | 36 / 36 | 0 / 8 | 0 / 4 | 0 | 0 |
| 错误放行一条还原 | 35 / 36 | 1 / 8 | 0 / 4 | 0 | 1 |
| 一个应通关样例收到无效输出 | 35 / 36 | 0 / 8 | 1 / 4 | 1 | 1 |

真实 CLI 连续通过 7 轮。每轮四份边界报告和一份开发集报告共发出 288 次回环请求，三次比较新增请求为零。另有独立测试把一个故事的改进与另一故事的退化设置为同等数量。全局计数持平时，分组比较仍拒绝候选。

## 运行成本

Windows 上同一 Go 1.26.5 测试程序预热后运行 7 轮。报告生成时，开发集每次发送 144 个本地请求，边界集只发送 36 个，减少 75%。墙钟耗时中位数由开发集的 97.665 ms 变为边界集的 54.064 ms，范围分别是 72.194–540.080 ms 与 39.315–193.180 ms。两者来自同一本地固定模型，差别包括范围大小和进程启动。

同一份 36 条报告在单 CPU 上交替测了 7 组。既有逐例计分中位为 1,917 ns、352 B、10 次分配。增加四组汇总后为 3,215 ns、912 B、13 次分配。

```powershell
New-Item -ItemType Directory -Force .local | Out-Null
$env:AI_EVAL_BINARY = Join-Path (Get-Location) '.local/ai-eval.exe'

go test -mod=readonly -v -count=1 ./cmd/ai-eval -run '^Test(AIEvalBoundaryCLI|Boundary)'

```
