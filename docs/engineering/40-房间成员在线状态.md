# 第 265 条 房间成员在线状态

房间成员卡展示「在线」或「离线」。在线表示当前服务进程中，这名成员在当前房间至少有一条握手成功的 WebSocket。加入房间、玩家席位和主持身份仍由 PostgreSQL 保存。已结束和关闭的房间保留原对局身份，成员卡停止显示实时标记。

- 房间快照批量读取内存中的连接计数，经过原成员授权后才返回 `members[].online`。房间中未加入的用户无法读取这些字段。
- 同一用户的首个连接上线和末个连接离线时复用 `changed` 通知。额外标签页、握手失败和重复释放不重复通知。新打开的页面使用既有快照刷新，通知发给已在房间里的其他连接。
- 主持断线暂停和重连恢复沿用房间状态变更。两种状态发生在同一次连接变化时合并提示。已收到通知的页面仍通过快照接口获取最新数据。

## 回归

本地 Windows Chromium 完整流程连续通过 3 轮，用例用时 14.4、15.3、13.2 秒。用例从房主和玩家两侧查看对方状态，并确认主持离线后对局暂停、重连后在线且可以继续提问。Vue 24 项测试及生产构建通过。

实际 Gin、PostgreSQL 与 WebSocket 连续 5 轮通过，另有 5 轮连接计数测试。每轮对同一个玩家开合三个标签页，共六次操作，旁观者只收到两条通知。首次上线通知耗时中位数 106 ms，范围 94–142 ms。末个标签页关闭后的通知中位数 34 ms，范围 29–38 ms。响应时间含本机到隔离 PostgreSQL 的 SSH 转发。
