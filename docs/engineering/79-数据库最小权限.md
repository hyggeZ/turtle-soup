# 第 780 条 数据库最小权限

当前服务用同一个 PostgreSQL 角色做启动迁移和日常业务。隔离 Docker PostgreSQL 16.15 新建迁移角色和运行角色。迁移角色拥有 schema 和表。运行角色获业务表的读写、序列使用权限，以及迁移记录的读取权限。[PostgreSQL 权限](https://www.postgresql.org/docs/16/ddl-priv.html) · [GRANT 语法](https://www.postgresql.org/docs/16/sql-grant.html)

| 对照 | 迁移角色 | 运行角色 |
| --- | --- | --- |
| 建表、修改表 | 成功，测试回滚 | 均拒绝，SQLSTATE 42501 |
| 刚创建库与迁移完成后运行现有 `migrations.Apply` | 迁移成功 | 两个时点均拒绝，SQLSTATE 42501 |
| 写迁移记录 | 可随迁移写入 | 拒绝，SQLSTATE 42501 |
| 注册登录、发布、创建与更新房间、读取快照、退出 | 现有默认角色覆盖 | 9 条路径均符合预期 |

三轮新数据库的 27 项 HTTP 检查全部通过，包括退出后旧 Cookie 再次请求返回 401。单轮测试用时约 0.61、1.41、0.51 秒，包含临时库、迁移、bcrypt 和业务请求。三轮生成的测试库与角色已清理，残留均为 0。

结果说明分离角色可以承载已测业务操作。现有进程即使连接已迁移的库仍会尝试执行需要建表权限的启动语句，生产切换需配独立的迁移入口并验证失败回滚。本次验收侧重权限边界，未替换实际服务角色或量测生产启动时延。本地复跑脚本、Go 夹具和日志位于 `.local/tech-780`。
