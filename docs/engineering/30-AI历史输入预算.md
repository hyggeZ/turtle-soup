# 第 135 条 AI 历史输入预算

固定取最近 12 轮有两个问题。问答很短时，可能提前丢掉有用线索；问答很长时，固定轮数仍会产生较大的输入。第 100 条评测中，唯一错判需要使用第 1 轮定义的物品代号，当局有 14 条问答。

- 数据库最多读取最近 24 条问题及已落库判定，按原时间顺序传给模型请求组装。
- 历史 JSON 最多 4 KiB。按编码后字节核对，包括换行、引号和 HTML 字符的转义。超出时移除较旧的完整问答，保留最近问答的顺序和重复次数。短局正常大小的历史保持原样。
- 字节限制只作用于历史字段。汤面、汤底、当前输入、系统指令和原有的 80 个输出 Token 上限沿用原设置。实际 Token 从百炼 `usage` 读取。请求组装版本记为 `v3`。

## 本地历史编码对照

Go 1.26.5，Windows/amd64，单线程，每组 250 ms，共 8 轮，以原版和候选交换执行顺序。仅计历史 JSON 编码。

| 合成夹具 | 保留轮数 | 历史 JSON | 中位耗时 | 分配字节及次数 |
| --- | ---: | ---: | ---: | ---: |
| 8 条短问答 | 8 → 8 | 593 → 593 B | 1.35 → 1.32 µs | 664 → 664 B，2 → 2 次 |
| 14 条短问答 | 12 → 14 | 889 → 1,037 B | 1.95 → 2.33 µs | 920 → 1,176 B，2 → 2 次 |
| 24 条长问答 | 12 → 4 | 11,473 → 3,825 B | 20.54 → 32.10 µs | 12,314 → 10,041 B，2 → 13 次 |

长夹具的历史 JSON 缩小 66.66%，编码耗时和分配次数增加。另有原文 1,152 B、编码后 7,225 B 的转义夹具，裁剪后为 3,914 B。问答过长仍可能让早期线索移出预算，以后可用长局失败样例单独评估保留策略。

## 百炼质量和调用耗时

在同一主机和百炼配置上，以 `v2 → v3 → v3 → v2` 顺序跑四轮 `qwen-plus`。每轮都是第 100 条的 24 条验证样例，题集指纹相同。两组配对都通过 `ai-eval compare`。

| 指标 | 第 1 组旧版 → 候选 | 第 2 组旧版 → 候选 |
| --- | ---: | ---: |
| 命中人工标签 | 23 → 24 | 23 → 24 |
| 调用失败、错误通关 | 0、0 → 0、0 | 0、0 → 0、0 |
| 正确还原命中 | 4 → 4 | 4 → 4 |
| 输入 Token | 8,467 → 8,594 | 8,467 → 8,594 |
| 输出 Token | 124 → 124 | 124 → 124 |
| 模型请求 P50 | 442.59 → 452.20 ms | 419.22 → 420.55 ms |
| 模型请求 P95 | 603.64 → 615.61 ms | 496.79 → 809.08 ms |

原版两轮都把 `holdout_clock_question_yes` 判为「无关」，候选两轮都判为人工标签「是」。采纳这项改动，换取目前已复现的长局质量收益。验证集输入 Token 增加 1.50%，候选 P95 两轮均较高，增幅差异较大。每轮只有 24 个调用，延迟不能代表长期线上表现。超长合成夹具只测请求历史大小和编码开销。

真实隔离 PostgreSQL 中通过 19 项 Agent 测试。覆盖最近 24 条有效问答的顺序、14 轮首轮线索、同一局范围、配额并发和旧操作重放。另有一项默认关闭的在线单测，本次真实模型对照由 `ai-eval` 独立执行。干净快照的全量 Go 回归与 `go vet` 均通过。
