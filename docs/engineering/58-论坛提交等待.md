# 第 450 条 论坛提交等待

发题和发表评论收到带有效 `Retry-After` 的 `429` 后，按服务端给出的秒数或标准 GMT 日期计算截止时间。等待期间保留输入和评论的剧透选项，禁用对应提交。期限到了恢复手动提交。缺少有效等待值时，继续显示接口原有错误。[HTTP Retry-After](https://www.rfc-editor.org/rfc/rfc9110.html#name-retry-after)

同一标签页按账号和操作类型分别记录截止时间。同一账号在题目之间切换时共用评论等待时间，发题和评论彼此独立。截止时间按时钟重新计算，页面卸载清理计时器。服务端 PostgreSQL 限额继续执行最终检查。

Vue 24 项测试、类型检查和生产构建通过，入口 JavaScript 增加 1,517 B。真实 PostgreSQL 并发发题与评论限额测试连续 3 轮通过。

前后对照用同一 Chromium 用例和 5 秒固定等待值。首次收到 `429` 后，分别尝试 4 次提交。旧版发题和评论各多发 4 次请求，换题还多发 1 次评论请求。候选三个场景均为 0 次，保留草稿及剧透勾选，等待结束也没有自动发送。无等待值时仍能看到原提示并主动重试。专项候选连续三轮 12/12 通过，隔离 PostgreSQL 的完整玩家和后台旅程也通过。
