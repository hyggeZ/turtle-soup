# 第 521 条 异常日志脱敏

Gin 的默认恢复中间件会在调试模式记录请求细节，在发布模式记录异常值。应用自定义恢复输出，只记固定错误信息、路由模板和服务生成的 Trace ID。请求仍返回 HTTP 500，后台运行日志能用同一个 Trace ID 查到状态与耗时。连接意外关闭的处理沿用 Gin。[Gin v1.12.0 恢复中间件](https://github.com/gin-gonic/gin/blob/v1.12.0/recovery.go)

| 同一个合成错误请求 | 默认恢复日志 | 自定义恢复日志 |
| --- | ---: | ---: |
| 调试模式可见的敏感标记 | 6/6 | 0/6 |
| 发布模式可见的敏感标记 | 1/6 | 0/6 |
| HTTP 状态 | 500 | 500 |
| 每次请求保留的后台记录 | 1 | 1 |

标记分别放在路径参数、查询串、Cookie、普通请求头、客户端自定义 Trace ID 和异常字符串中。两种模式均核对响应、日志与后台追踪记录。这个改动衡量泄漏字段数，没有将异常路径测试换算成接口吞吐增益。Nginx 访问日志与真实部署数据不在本次测试范围。

```powershell
go test ./cmd/server -run TestRecoveryKeepsOnlyTraceMetadata -v
```
