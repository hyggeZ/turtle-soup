# 离席后的还原判定

## 问题与处理

玩家原来可以先提交还原，再自行退出玩家席位或获准查看汤底。只要其他选手还在，房间仍进行中；主持随后把旧还原判为“正确”时，竞答会把已离席者写成胜者。共探也会错误地把离席者标记为答对。主持界面一直显示这条还原的判定按钮。

现在主持判定前同时检查原还原仍未回复、提交者当前仍是玩家。玩家退席或获准看底时，在同一个房间事务内给其未判定还原写入一条“已失效”结果，再改变成员身份。房间写操作原本就持有同一行锁，因此判定和退席按提交顺序串行：先判定的结果有效，先退席的旧还原不能再被判定。前端对历史遗留的无回复、作者已离席的还原也隐藏判定按钮。私人还原正文仍由原有服务端快照按身份过滤。

## 验收与开销

- 修复前的真实 PostgreSQL 回归在竞答、共探的“自行退席”“获准看底”四种组合中都复现：旧还原被判正确时错误返回 200，竞答直接结束。
- 修复后四种组合均拒绝旧判定，房间保持进行中、离席者不标记答对、不出现错误胜者；每条旧还原只有一条失效结果，其他玩家看不到私人正文，并能继续推理和完成对局。三种主持判定均不能处理历史遗留的离席还原。
- 退席与判“正确”同时发起的真实 PostgreSQL 用例只接受两种串行结果，且原还原恰好有一条回复；定向测试连续运行 5 次、`-race` 运行 1 次均通过。本地真实 PostgreSQL 上 `go test ./... -count=1` 通过，`web` 的 `npm run build` 通过。
- 对“正确”的主持判定，原实现分别查询事件是否可判和作者 ID；现在合为一次查询，减少 **1 次数据库往返**。对“错误”“不完整”的判定，查询数不变。退席和看底同意各增加 **1 条 `INSERT ... SELECT`**，没有待判还原时也会执行。快照查询数和响应结构不变。尚无稳定端到端延迟样本，不能把查询次数变化换算成毫秒收益。
