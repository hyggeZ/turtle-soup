# 第 123 条 配额和房间数据对账

`turtle-admin audit` 一次输出 AI 日配额与房间成员的对账结果。查询使用同一个 PostgreSQL 只读重复读事务，报告只包含日期、计数、房间编号和固定异常类型。命令不执行迁移或修改数据。

- **配额**使用写入配额时的数据库 `CURRENT_DATE`，默认核对含今天在内的 7 天，可设为 1–31 天。全站低于账号合计是明确异常，包含全站计数缺行的情况。全站高于账号合计只提示复核，因为硬删除账号会同时移除该账号的用量记录；停用账号会保留用量。
- **房间**核查房主是否仍在成员表、主持指针和角色是否匹配、玩家是否超员或已经看底，以及竞答胜者和回合成员是否自洽。报告中的总数按异常明细计，最多列出前 20 条用于定位。尚未选主持的等待房、旧竞答玩家离席后仍等待主持答题、已结束竞答里还有其他玩家，都属于合法状态。
- **调度**提供 systemd 每小时运行配置。手动执行 `turtle-admin audit -days 7` 时，正常或仅有待复核项退出 `0`，明确异常退出 `2`，运行失败退出 `1`。定时任务沿用应用用户，结果可用 `journalctl -u turtle-soup-audit.service` 查看。

## 验收和开销

在 `mine` 的一次性 PostgreSQL 测试库通过三项集成测试。包含缺行、账号硬删除、时间范围、六类房间异常和样本上限。CLI 实测依次报告正常、全站缺行并退出 `2`、补回合成记录后恢复正常。填补发生在测试夹具中。

同一数据库预置 40,000 条用户日用量和 1,000 个正常房间。按 31 天、每组 25 次交替测量。对照组模拟管理员在同一个只读快照里逐日查两次，得到 62 条 SQL；新命令批量核对配额，并额外核对房间。配额输出逐次一致。

| 方案 | P50 | P95 |
| --- | ---: | ---: |
| 手工逐日配额查询 | 107.01 ms | 117.84 ms |
| 批量配额与房间对账 | 11.69 ms | 14.43 ms |

数据反映批量读取的开销，适用于本次合成规模。业务请求不触发对账。部署新版管理命令后，可把 `deploy/turtle-soup-audit.service` 和 `deploy/turtle-soup-audit.timer` 安装到 `/etc/systemd/system/`，执行 `systemctl daemon-reload` 后启用 `turtle-soup-audit.timer`。本次只校验定时表达式和实际命令，线上定时器未启用。
