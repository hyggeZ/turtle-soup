# 技术词典 251–500 项适用性评估（工作稿）

口径：保持《技术词典_频率排行.md》的原序号。本表仅是针对当前 `turtle-soup` 的设计判断，**“接受”不表示已实现**；只有写明“现有”的项才可在当前简历陈述。应用边界是 Go/Gin 模块化单体、PostgreSQL、Vue、WebSocket 房间、百炼 Qwen 单人主持。新组件需按项目要求逐项实施、回归、测量和独立提交。性能词条是测量方法，不自动带来提速；模型质量词条应报告误判与成本，不用 RPS 代替。

## 251–300

| 265 | 在线状态 | 已验证 | 支持房间成员在线状态和首连、末连通知，快照每次仍为 7 次 SQL，见[房间成员在线状态](../40-房间成员在线状态.md)。 |
| 266 | ACK/NACK | 暂不 | 当前 WebSocket 仅推送“已变化”，客户端再拉权威快照；无需对每条提示做消息 ACK。若未来异步队列须加。 |
| 267 | ACL | 接受（现有） | 管理员、房主、主持、玩家、旁观者的对象权限应由后端复核；对查看汤底和私有还原继续做越权回归。 |
| 268 | AG-UI | 暂不 | 当前 AI 单次判定无可流式呈现的长步骤；待互动型 Agent 前端出现，再评估协议互通收益。 |
| 269 | AgentScope | 不适用 | 单一受约束 Qwen 主持，没有多 Agent 协作；引入框架只会增加状态和调试层。 |

| 271 | asyncio | 不适用 | 服务端为 Go，调用 Qwen 使用 Go `http.Client`；没有 Python 异步服务。 |
| 272 | B+ 树 | 接受（基础） | 用 PostgreSQL B-tree 索引解释题目筛选、游标翻页与房间查询的执行计划；不自造索引结构。 |

| 274 | Blackboard | 暂不 | AI 主持只有一次模型决策，没有共享任务状态的多 Agent；避免为概念新增数据库表。 |
| 275 | Celery | 不适用 | 没有 Python Worker；若未来后台任务增加，先定义 Go 任务与持久状态。 |
| 276 | Context Precision | 已验证 | 对 14 个长局样例标注早期问答，现行检索命中 9/10 条且无误选，见[AI 长局证据检索评测](../42-AI长局证据检索评测.md)。 |
| 277 | CrewAI | 不适用 | 无多 Agent 角色协作；Go 服务直接调用 Qwen 判定即可。 |
| 278 | CUDA | 不适用 | 使用百炼托管推理，不管理 GPU 内核。 |
| 279 | DeerFlow | 暂不 | 通用 Agent 工作流框架与受限三选一主持不匹配，除非未来加入长链研究任务。 |
| 280 | Docling | 暂不 | 海龟汤题目是短文本输入，不解析复杂 PDF；如引入资料导入再评估。 |
| 281 | Eval Harness | 已验证 | CI 编译并调用真实 `ai-eval`，用 24 条独立样例生成报告并核对三类退化的比较结果和退出码，见[AI 评测命令质量回归](../43-AI评测命令质量回归.md)。 |

| 283 | Git Worktree | 接受（工程） | 大改动可隔离并行实验，避免 UI、追踪、缓存的未完成修改混入同一提交；不是产品技术。 |
| 284 | Grafana | 暂不 | 后台已有近请求统计；指标时间序列达到持续运营规模后，再配合 Prometheus 可视化。 |
| 285 | gRPC | 暂不 | 目前模块化单体与浏览器客户端，内部没有跨进程调用；拆服务之前没有 RPC 边界收益。 |
| 286 | InnoDB | 不适用 | 唯一权威业务库是 PostgreSQL；研究其 MVCC/索引即可，无须引入 MySQL 存储引擎。 |
| 287 | Langfuse | 暂不 | AI 判定当前只记录枚举、耗时、Token；先实现隐私安全的自有 trace 与评测，确有跨版本分析需求再接。 |
| 288 | LogRecord | 接受（候选） | 后台改密码、封禁或删除题目等管理操作需审计“谁对何对象做何动作”，与请求耗时日志分开，避免记录敏感正文。 |
| 289 | LoopDetector | 不适用 | Qwen 每次单次返回结果，没有工具循环；Agent loop 开发后才需循环与预算检测。 |
| 290 | LRU | 暂不 | 热点题目缓存先按读写和容量量测选 TTL/淘汰；不因 LRU 名称自制缓存层。 |
| 291 | Map | 接受（现有） | 房间 `liveHub` 用 map 维护连接集合；需继续保护锁与断线删除，避免增长无界。 |
| 292 | Mock | 接受（现有） | `agent.Decider` 和 HTTP 客户端接口可替换，离线测试不消费百炼额度；扩充故障与超时场景。 |
| 293 | MongoDB | 不适用 | 用户、题目、房间及事件强关系且事务重要，PostgreSQL 足够；双库增加一致性负担。 |
| 294 | MTP | 不适用 | 多 Token 预测属于模型训练/推理底层，百炼 API 不开放该控制面。 |
| 295 | Nacos | 暂不 | 单服务部署无服务发现；若未来拆成多个可独立扩缩的服务，再比较 K8s DNS 等方式。 |
| 296 | NDCG | 暂不 | 暂无机器排序或检索；题目广场排序如做个性化推荐，先建立相关性标注再算 NDCG。 |
| 297 | Nginx | 接受（现有） | `deploy/provision.sh` 已配置反向代理；核对 WebSocket 升级、读超时、静态资源缓存与真实 IP 边界。 |
| 298 | Ollama | 暂不 | 当前百炼 Qwen 托管，部署环境未证明可稳定本地推理；可作离线模型对照而非生产依赖。 |
| 299 | OpenCode | 不适用 | 是开发助手，不是海龟汤服务能力；不应写成产品技术栈。 |
| 300 | Outbox Relay | 暂不 | 当前无跨服务事件队列；若新增 Kafka 任务，先确认“数据库提交与发消息”原子性问题，再采用 Outbox。 |

## 值得排入逐项实验的组合（按依赖顺序）

1. **观测与回归基础**：第 347/421/486 项合并为一次“请求与 AI 阶段追踪完善”，先采现有性能基线，再加阶段开始/结束、首失败位置与后台视图；第 373/261/385 项建立真实 PG + 浏览器行为回归。每个仍按用户要求分独立变更/报告，合并的只是概念重复，不能重复宣称提速。
