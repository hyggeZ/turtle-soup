# 技术词典 251–500 项适用性评估（工作稿）

口径：保持《技术词典_频率排行.md》的原序号。本表仅是针对当前 `turtle-soup` 的设计判断，**“接受”不表示已实现**；只有写明“现有”的项才可在当前简历陈述。应用边界是 Go/Gin 模块化单体、PostgreSQL、Vue、WebSocket 房间、百炼 Qwen 单人主持。新组件需按项目要求逐项实施、回归、测量和独立提交。性能词条是测量方法，不自动带来提速；模型质量词条应报告误判与成本，不用 RPS 代替。

## 值得排入逐项实验的组合（按依赖顺序）

1. **观测与回归基础**：取连接阶段（347）、真实 PostgreSQL 和浏览器回归（261/373）已验证。第 421、486 项再核对独立需要，第 385 项补关键界面的可访问名称、说明和键盘流程。
2. **权限与 AI 安全**：第 453/267 项对对象级越权补表驱动测试；第 304 项补玩家输入的提示词注入评测。以剧透泄漏/错误完结率为主要指标，速度为次要指标。
3. **AI 质量**：第 281/313/470/303/402/423 项依次固定评测集与版本、人工标签规则、难例校准、分类精确率与忠实度。`agent.Evaluate` 已有矩阵和误判完结率，增量要聚焦空缺。
4. **业务一致性**：后台审计（288/333）、题目编辑版本（329）、断线快照补查（334）和服务端会话（335）已验收。在线状态与慢连接背压由第 265 和 342 项验证。
5. **有测量前提的性能改造**：先用第 465/457 项固定负载与真实交互测量；若公开题目/大厅读确实成为瓶颈，再引第 358 项 Redis 并一并处理第 339/340 项一致性与失效。只有观察到同键回源风暴才试第 314 项 singleflight。

后续项如 gRPC、Kafka/Outbox、Kubernetes、RAG、多 Agent、模型推理内核优化，应当由明确的新功能或可复现瓶颈触发；当前受限主持与单体架构无法给它们合理的落点。
