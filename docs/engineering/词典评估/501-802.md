# 技术词典 501–802 项适用性评估

依据《技术词典_频率排行.md》原顺序。当前产品是 Go/Gin 模块化单体 + PostgreSQL、Vue/Vite 网页、WebSocket 真人房间、百炼 Qwen 单人判定；移动端仍是规划。**“接受（候选）”仅表示有合理实验位置，不代表已经实现或应立即写入简历。** 对重复技术词合并成一次实施项；每次实验仍需独立基线、回归、数据报告和提交。

## 可以进入逐项实装队列的主题与先决条件

1. **当前追踪验收**：第 601/704/741/767 项应作为一次“完整请求阶段与取消传播”工作，先测现状，再补 trace 时间线、首失败位置、Context 传递和后台展示。第 616 项结构化日志已存在，不重复声称新加。新数据要测日志量、请求 P95 与漏记率。
2. **可复现性能测量**：第 663 项 Go Benchmark 已有，补第 678 项固定 k6 场景和第 707 项 SQL 统计。第 714/612 项仅在 CPU 热点出现时使用。比较前后必须同设备、同数据量、同并发、相同版本模型；第 617/638 项用于评估波动。
3. **AI 质量优先**：第 664/605 项冻结并整理标注集，第 515/611/731/800 项测多次稳定性、消融和错误通关率；只有显著质量提升才开第 656 项模型/提示词开关，并考虑第 789/774 项灰度或影子模式。付费在线评测需额度控制且不得记录用户汤底。
4. **并发与业务安全**：第 610/756/764/783/784 项针对状态机 fuzz、XSS/CSP、锁顺序和外部 AI 池隔离。第 760/661 项把回归设为 CI 门禁；第 780/791 项校验数据库和密钥权限。
5. **缓存与搜索仅在需求出现后**：若公共详情读成为瓶颈，第 728 项 Redis String 才能实验，必须同时做第 766 项冷热对照、失效/权限测试；第 613/565 项在有更新竞争或可接受陈旧数据时才尝试。题库搜索确定后，再从第 559/581 项文本检索起步，逐步比较向量/ANN。

用户提出的 Kafka、Protobuf、服务发现、gRPC 等中间件，在当前单体和仅变化通知的架构下没有必要的消息/RPC 边界；决定加入它们的门槛应当是具体异步业务或独立扩缩的服务及其压测证据。
