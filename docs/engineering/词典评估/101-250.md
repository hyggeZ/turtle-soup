# 技术词典 101–250 项与 turtle-soup 的关系

按《技术词典_频率排行.md》原序；“可加入”均写出最小落点与验收指标。语言、平台和开发工具不会被当成产品能力。

101. **Query Understanding｜需证据**：玩家提问类型已显式区分；只有题目搜索出现多条件自然语言查询时才需意图路由。
102. **Agent Loop｜需证据**：现有 AI 主持一次判定即可完成动作，先用长局坏例证明需要循环调用工具。
103. **Coding Agent｜不适合**：可辅助开发，但游戏不提供代码检索或文件编辑能力。
104. **JVM 类加载｜不适合**：服务不运行 JVM。
105. **Milvus｜不适合**：题库规模和检索需求不足以支撑独立向量集群。
106. **RabbitMQ｜需证据**：内容审核、通知等慢任务出现持续积压后才需要 broker。
107. **Android｜需证据**：Flutter App 尚未落地；需要原生通知或系统能力时再写 Android 桥接。
108. **Pull Request｜需证据**：当前用户要求直推 main；多人协作或审查门禁出现后再用 PR。
109. **React｜不适合**：网页已采用 Vue，重写不增加玩法价值。
110. **vLLM｜不适合**：Qwen 由百炼托管，项目没有自管 GPU 模型服务。
111. **Bloom Filter｜需证据**：无大量无效题目 ID 查询；它也不能决定访问权限。
112. **Chroma｜不适合**：尚无向量检索语料，另设向量存储没有收益。
113. **Pydantic｜不适合**：Go 后端已校验请求和模型输出，不需要 Python DTO 库。
114. **pytest｜不适合**：正式测试主体是 Go testing 和前端构建，暂无 Python 服务测试集。
115. **Redisson｜不适合**：Go 与 PG 行锁承担并发控制，不用 Java Redis 客户端。
116. **Supervisor｜不适合**：单局主持没有多 Agent 调度对象。
117. **向量数据库｜需证据**：先建立题目语义搜索及 Recall@K 标注集，再决定是否需要专用存储。
118. **数据库事务｜已用**：账号、房间、揭底和 AI 配额均在 PG 事务中维护一致性。
119. **结构化输出｜已用**：Qwen 分类结果由后端按允许值验证，非法结果拒绝提交。
120. **Rust｜不适合**：现无已测出的 Go 性能瓶颈或共享原生核心。
121. **Bad Case Analysis｜已用**：固定评测集加入否定句、提示注入和错误还原边界样例。
122. **Prometheus｜已验证**：加入房间和 AI 判定复用追踪计时，增加回环端口供抓取。真实 Prometheus 查询验证错误率、P95 和应用重启前后的时间序列，见[运行指标](../28-Prometheus运行指标.md)。
123. **数据对账｜已验证**：管理命令在同一只读快照内核对 AI 全站配额和房间关系，区分明确异常与待复核差额。定时器按需启用，见[配额和房间数据对账](../29-配额和房间数据对账.md)。
124. **高可用｜需证据**：单机已有健康检查和发布回滚；先定义可用性目标与停机时长，再决定副本切换。
125. **BGE-M3｜需证据**：只在已标注题目搜索里比较 Recall@10，不能因模型热门接入。
126. **BGE-Reranker｜需证据**：先有召回候选和相关性标注，再测重排后 MRR 与延迟。
127. **Handoff｜不适合**：单局主持无需在多个 Agent 间转交状态。
128. **JMM｜不适合**：Go 并发遵循 Go 内存模型。
129. **Kafka｜不适合**：当前没有需回放的大规模事件流；对局写入 PG 即可。
130. **KV Cache｜不适合**：百炼托管推理，应用无法控制其内部缓存策略。
131. **LangChain4j｜不适合**：项目没有 Java AI 服务。
132. **LoRA｜需证据**：先积累足量标注坏例和独立测试集，再比较微调与提示词的误判率和成本。
133. **MinIO｜不适合**：汤题目前是文本，无图片或附件对象。
134. **Qdrant｜需证据**：若语义检索经标注集证明价值，再与 PG 向量扩展比较质量和运维成本。
135. **Token Budget｜已验证**：AI 历史取最近最多 24 条，实际发送的历史 JSON 以 4 KiB 为上限，用百炼 usage 记录真实 Token。长局坏例两轮复测均修复，延迟与输入成本见[历史输入预算](../30-AI历史输入预算.md)。
136. **事务隔离级别｜已用**：PG 默认读提交配合行锁和唯一约束；并发入场与额度争抢有集成测试。
137. **死信队列｜不适合**：当前没有异步消息消费者，先不建空 DLQ。
138. **空值缓存｜需证据**：公开题目缓存上线后若无效 ID 回源显著，再加短负缓存并测 DB 查询下降。
139. **缓存击穿｜需证据**：没有热键缓存就无击穿问题；未来应测单热键到期时回源峰值。
140. **iOS｜需证据**：Flutter 端尚未实现；需要 iOS 原生能力时再写桥接。
141. **Dify｜不适合**：已有 Go 业务规则和 Qwen 调用，低代码重建会削弱规则可审计性。
142. **Shell｜已用**：`deploy/release.sh` 和服务器部署脚本承担发布工作。
143. **Benchmark｜已用**：HTTP 最小请求、房间快照与长局规模已有固定基准及历史结果。
144. **CLI｜已用**：`cmd/ai-eval` 和 `cmd/admin` 是独立维护命令。
145. **Docker Compose｜已用**：本地 PostgreSQL 由 `compose.yaml` 启动。
146. **Human-in-the-loop｜需证据**：真人主持是独立玩法；AI 低置信人工复核需先有争议样本与介入流程。
147. **LLM-as-a-Judge｜需证据**：现有三分类有人工标注金标准；开放式线索质量出现后再校准模型裁判。
148. **Plan-and-Execute｜不适合**：游戏判定没有需规划的多步任务，固定状态机更易验证。
149. **QPS｜已验证**：公开题目与长局主持快照新增真实回环 HTTP 吞吐基准。10,800 次正式请求全成功，已记录并发级别、延迟分位和连接池等待，见[真实 HTTP 吞吐基线](../31-真实HTTP吞吐基线.md)。
150. **Redis MULTI/EXEC｜不适合**：尚无 Redis 状态；PG 事务已保证核心写入。
151. **Spring AI｜不适合**：Go 已直连 Qwen，项目没有 Spring AI 服务。
152. **Spring Cloud｜不适合**：当前单体无需 Java 微服务配置、注册和网关套件。
153. **Spring Interceptor｜不适合**：Gin 中间件已处理 HTTP 横切逻辑。
154. **Synchronized｜不适合**：Go 不使用 JVM monitor，当前同步使用 `sync.Mutex` 和 PG 锁。
155. **Transactional Outbox｜需证据**：若发布题目同时发异步审核事件，才需事务内写 outbox；先测丢消息与重复处理。
156. **TTFT｜不适合**：AI 只返回短 JSON 判定、不流式展示，用户等待更应看整次 P95。
157. **令牌桶｜需证据**：现有固定窗口限流够用；若正常用户遭突发误限，再测允许突发量和保护效果。
158. **回归测试｜已用**：房间权限、幂等、AI 边界坏例已固化为测试。
159. **多级缓存｜需证据**：单层公开题目缓存尚未证明瓶颈，双层失效会增加复杂度。
160. **顺序消费｜不适合**：无异步消息消费者；房间事件依赖 PG ID 和事务顺序。
161. **HTTP｜已用**：Go API、Vue 请求和 Nginx 入口均使用 HTTP 语义。
162. **WebSocket｜已用**：多人房间实时状态和主持掉线处理使用双向连接。
163. **设计模式｜已用**：Decider 接口隔离真实 Qwen 与测试替身，按具体替换需求使用。
164. **API 网关｜不适合**：现有 Nginx 入口与单体路由足够，无多个下游服务要统一治理。
165. **Context Engineering｜已验证**：按当前引用补入同局较早的原始问答，优先近期代号并复用 4 KiB 预算。50 轮夹具复测见[长局历史原文检索](../32-长局历史原文检索.md)。
166. **Transformers（Hugging Face）｜不适合**：百炼托管推理，不在项目内加载或训练模型。
167. **容灾｜已验证**：在私有 PostgreSQL 实例两次恢复历史归档，再用临时只读快照验证含业务数据的恢复。历史归档较旧，见[恢复时点与验收数据](../33-PostgreSQL恢复演练.md)。
168. **心跳｜已用**：房间 WebSocket 定期 Ping，连接失活影响主持状态。
169. **AQS｜不适合**：Java 同步器机制与 Go 服务无关。
170. **Broker｜需证据**：没有后台消息积压或多消费者，独立代理没有任务可路由。
171. **DashScope｜已用**：单人主持通过百炼 Qwen API 调用模型。
172. **DPO｜不适合**：项目不训练底座模型，也没有偏好对数据。
173. **Elasticsearch｜需证据**：当前题目检索可由 PG 完成，先测题库规模与搜索延迟再考虑独立集群。
174. **Node.js｜已用**：Vue/Vite 构建依赖 Node.js；线上业务接口不由 Node 运行。
175. **pgvector｜需证据**：只有语义找题在标注集上比结构化筛选更好，才加 PG 向量列并测 Recall@10/P95。
176. **Recall@K｜需证据**：题目搜索尚无相关性标注，不能报告召回率。
177. **SDK｜不适合**：目前只有本项目 Web 客户端，无外部开发者集成需求。
178. **Spring MVC｜不适合**：HTTP 接口由 Gin 实现，不运行 Spring。
179. **SQLAlchemy｜不适合**：Go 的 pgx 已覆盖数据库访问，无 Python ORM 层。
180. **TTL 随机抖动｜需证据**：未来缓存大量同批键时可测集中回源，现无缓存过期洪峰。
181. **Worker｜需证据**：尚无需要脱离请求运行的审核或通知任务；先测单次任务时长和排队量。
182. **元数据过滤｜已用**：选题按本格/变格、难度、恐怖程度及可见性在 PG 过滤。
183. **HarmonyOS｜不适合**：当前网页端优先，未来 Flutter App 也未提出鸿蒙原生需求。
184. **Hive｜不适合**：项目无大规模离线文件仓库或批量 SQL 分析。
185. **数据标注｜已用**：AI 固定评测集的人为期望类别和边界样例是判定金标准。
186. **Agent Evals｜已用**：现有 Qwen 主持评测覆盖分类、误判结束、延迟和 token；尚不代表多步 Agent 评测。
187. **AutoGen｜不适合**：单人主持没有多 Agent 消息编排需求。
188. **Coze｜不适合**：Go 后端已承载权限、状态和模型调用，低代码复制流程无收益。
189. **CSS｜已用**：Vue 页面有独立样式及响应式断点。
190. **HTML｜已用**：登录、列表、房间、后台均以语义表单和页面结构呈现。
191. **RPC｜不适合**：服务尚未拆部署单元，不存在跨服务内部调用。
192. **AIOps｜不适合**：当前只需查看日志并定位问题，自动故障处置没有必要。
193. **CI/CD｜已验证**：GitHub Actions 在 main 上并行执行 Go 与 PostgreSQL 集成回归和 Vue 构建。首个托管运行通过，见[自动回归](../34-GitHub自动回归.md)。
194. **Context Window｜已用**：默认保留最近最多 24 轮，根据当前引用补入同局旧问答，历史 JSON 共用 4 KiB 预算。见[长局历史原文检索](../32-长局历史原文检索.md)。
195. **DDD｜已用**：以 account/forum/room/agent/admin 分业务边界组织单体代码；不声称完整 DDD 战术模式。
196. **Electron｜不适合**：用户计划网页与 Flutter App，无桌面客户端需求。
197. **分库分表｜不适合**：单库数据量很小，跨分片查询和迁移会先增加风险。
198. **动态配置｜需证据**：模型及服务参数变更频率低，现有环境变量加重启可控。
199. **后训练｜不适合**：项目调用托管模型，无训练数据与算力规划。
200. **对象存储｜不适合**：当前没有附件、音频或图片上传；文本仍适合 PG。
201. **沙箱生命周期｜不适合**：海龟汤只处理受限文本判定，不运行用户代码或独立沙箱环境。
202. **ASR｜需证据**：目前玩家输入文字；若验证语音房需求，再测真实口语转写的字错率与端到端延迟。
203. **Attention｜不适合**：项目调用托管 Qwen，注意力实现属于模型内部，不是应用后端的可控优化点。
204. **BF16｜不适合**：模型由百炼托管，项目没有本地推理或训练精度可调。
205. **Channel｜已用**：Go 服务关闭信号和房间实时通知使用 channel，配合 Context 管理连接生命周期。
206. **Cross-Encoder｜不适合**：当前题目列表按明确字段筛选，没有需要语义重排的大型召回集合。
207. **DAG｜不适合**：房间动作与三分类 AI 判定是短事务/单次调用，没有复杂任务依赖图。
208. **DeepSpeed｜不适合**：未训练大模型，也没有多 GPU 训练任务。
209. **F1 Score｜已验证**：问答与还原各自计算逐类和宏 F1，比较同一题集的模型版本与逐类差值。历史报告可离线重算，见[逐类与宏 F1](../35-AI逐类与宏F1.md)。
210. **GPT｜需证据**：可作为 Qwen 的候选对照，但先用同一盲测集比较泄底率、判定 F1、P95 延迟及单局成本，再决定是否接入。
211. **GRPO｜不适合**：没有可验证奖励、训练流水线和足量标注，托管模型后训练超出应用范围。
212. **Guardrails｜已用**：服务端限制游戏权限、调用配额和 AI 三分类输出，错误格式拒绝落库；继续用泄底与越权样例验收。
213. **JSON Schema｜需证据**：当前 Qwen 只输出一个 result 字段，已做严格 JSON 解码和枚举校验；待工具参数或输出结构变复杂再引入 Schema。
214. **JSONL Transcript｜已用**：请求链路已按 JSONL 写 trace；AI 对话持久化在 PG，不应把含汤底的原文复制进可下载日志。
215. **kNN｜不适合**：题目尚无语义相似检索需求，现有分类和关键词查询足够。
216. **Mutex｜已用**：进程内限流器、房间实时连接表和 trace 缓冲用 sync.Mutex；跨实例状态仍由 PG 约束。
217. **Neo4j｜不适合**：题目、玩家、房间是常规关系模型，PG 已满足查询，无复杂图路径问题。
218. **PPO｜不适合**：项目不训练策略模型，现有质量问题宜先通过评测集与提示词迭代处理。
219. **Query Rewrite｜不适合**：现阶段无 RAG 或复杂多轮知识检索，题目筛选无需模型改写查询。
220. **RBAC｜已用**：普通用户、管理员、超级管理员已有服务端角色权限；题目归属与房间身份另行校验。
221. **Redis SET NX｜不适合**：房间关键动作已有 PG 行锁及唯一幂等键，跨实例 Redis 锁会增加一致性负担。
222. **RLHF｜不适合**：没有训练模型与人类偏好数据，应用层先记录可审查的误判样例。
223. **SaaS 多租户｜不适合**：这是单一游戏社区，用户账号和管理员角色不是租户边界。
224. **Session｜已用**：登录使用 PG 持久会话与不透明 Cookie，注销和改密可撤销会话。
225. **Slice｜已用**：Go 查询结果、历史问答和房间成员使用切片；它是基础语言结构而非单独的架构亮点。
226. **Spring AI Alibaba｜不适合**：后端已定 Go，百炼通过 HTTP 接入；Java AI 框架不能改善现有链路。
227. **StateGraph｜需证据**：AI 主持当前只有固定问答/还原判定；若增加多步工具与可恢复分支，先画状态转换并测失败恢复率。
228. **Tool Registry｜需证据**：AI 主持暂不调用外部工具；出现搜索题库或计分工具时再建白名单注册、参数验证与权限测试。
229. **TTS｜需证据**：当前无语音玩法；若玩家确实需要语音主持，再测音频生成 P95、成本及主观可懂度。
230. **XXL-Job｜不适合**：这是 Java 任务调度平台，当前 Go 服务且无复杂批量作业。
231. **多租户隔离｜不适合**：项目不存在组织/租户维度；现有用户对象级授权更贴切。
232. **幂等键｜已用**：房间操作及 AI 调用绑定 operation_id，结合请求摘要和 PG 唯一约束在重试时回放原结果。
233. **延迟消息｜不适合**：竞答回合超时目前按服务器时钟和 PG 状态推进，无需为每回合建立消息队列。
234. **异步缓存重建｜需证据**：题目列表尚未证明热点回源；引入缓存后先测过期并发时的 PG QPS 与 P95 再考虑后台刷新。
235. **微信小程序｜不适合**：当前客户端规划是 Vue 网页和 Flutter App，额外平台会分散实现与测试。
236. **指数退避｜已验证**：房间 WebSocket 使用带抖动的封顶指数退避。1,000 客户端同时断线模拟中，每 100 ms 峰值重连由 1,000 降至 112，见[房间断线重连退避](../11-断线重连退避.md)。
237. **故障注入｜已验证**：WebSocket 断连、Qwen 超时和 PostgreSQL 拨号拒绝各验证 5 次。检查恢复、幂等和汤底权限，见[故障注入与恢复](../36-故障注入与恢复.md)。
238. **旁路缓存｜需证据**：若公开题目列表确有读热点，可对列表/预览试 Redis Cache-Aside，测命中率、PG QPS、P95 和下架后的陈旧可见率。
239. **查询执行计划｜已用**：已有 PG EXPLAIN ANALYZE 验收记录；后续针对明确慢查询重复比较扫描行数、耗时与索引命中。
240. **消息回放｜已用**：房间重连可按事件游标补取历史消息；这只恢复玩家视图，不重新执行扣费或游戏动作。
241. **短期记忆｜已用**：AI 主持保留本局最近最多 24 轮有效问答。长局可补入匹配的旧原文，近期问答和旧原文共享 4 KiB 历史编码预算，见[历史输入预算](../30-AI历史输入预算.md)与[长局历史原文检索](../32-长局历史原文检索.md)。
242. **端到端测试｜已验证**：Playwright 走通注册登录、发题、开房、断线恢复、AI 判定和后台审核。本机连续 3 轮和 GitHub Chromium 均通过，见[浏览器端到端回归](../37-浏览器端到端.md)。
243. **缓存雪崩｜需证据**：当前无大规模业务缓存；若加 Redis，再测试同批 TTL 到期及缓存不可用时的 PG QPS、错误率和降级效果。
244. **行锁｜已用**：房间动作、查看汤底、管理员操作与 AI 状态流转使用 SELECT FOR UPDATE 序列化冲突写。
245. **API 契约｜可加入**：为游戏/后台 HTTP 接口及 WebSocket 事件整理版本化请求、响应、错误和权限契约，CI 校验前后端；统计契约偏差数与兼容回归数。
246. **BFF｜需证据**：目前 Go API 直接服务 Vue，若 Flutter 页面出现多次高延迟往返，再做页面聚合端点并比较请求数与首屏 P95。
247. **Kotlin｜不适合**：移动端计划采用 Flutter，单独原生 Android 实现会增加双端维护成本。
248. **Mobile BFF｜需证据**：Flutter 端尚未形成请求画像；仅在移动网络下页面请求过多时，用聚合接口验证 RTT 和首屏 P95 改善。
249. **NoSQL｜不适合**：它是数据库范畴而非具体优化，现有事务与关系数据适合 PG；Redis 需凭缓存场景单独论证。
250. **Rust Core｜不适合**：游戏规则由 Go 服务端权威执行，Flutter/Vue 无需共享本地 Rust 核心或 FFI。
